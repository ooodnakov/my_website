# Terminal session contract

`client/src/lib/terminal/session.ts` is the UI/backend boundary. The React terminal owns xterm presentation and renders session output; exactly one session owns interactive input and command execution. A session must implement explicit `start()` and idempotent `dispose()`, state subscription (`idle`, `ready`, `busy`, `failed`, `disposed`), output subscription, resize notification, language changes, and visitor actions. `runVisitorCommand()` returns whether a fixed, own-key allowlisted action was accepted, never whether it completed successfully.

`input` makes routing explicit: `legacy-shell-key-events` means the lightweight `Shell` handles xterm key events; a future `session-byte-stream` input carries `sendBytes(bytes)`. The React adapter attaches no data listeners for the legacy owner; for the byte-stream owner, xterm text from `onData` is UTF-8 encoded, while each `onBinary` character contributes its low eight bits. The two owners must never be attached together. Stream output is text/bytes or a clear-screen event; the React renderer consumes the event stream. Session subscribers and state observers must be detached during disposal. Async startup and command completions must not update disposed sessions; startup errors transition to `failed`.

`LegacyTerminalSession` is the current implementation. It owns the existing `Shell` and `VirtualFileSystem`, keeps history/VFS behavior local, and accepts only the fixed `VisitorCommand` vocabulary. Its no-op `resize()` is intentional: the surrounding `FitAddon` sizes legacy xterm and there is no remote process to signal. A guest implementation must define readiness/busy transitions, output buffering, resize bounds, and error/disposal behavior without changing the visitor action API. No guest runtime, image, worker, network access, or asset download is part of this interface change.
