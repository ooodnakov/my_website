# Terminal session contract

`client/src/lib/terminal/session.ts` is the UI/backend boundary. The React terminal owns xterm presentation and renders session output; exactly one session owns interactive input and command execution. A session must implement explicit `start()` and idempotent `dispose()`, state subscription (`idle`, `ready`, `busy`, `failed`, `disposed`), output subscription, resize notification, language changes, and visitor actions. `runVisitorCommand()` returns whether a fixed, own-key allowlisted action was accepted, never whether it completed successfully.

`input` makes routing explicit: `legacy-shell-key-events` means the lightweight `Shell` handles xterm key events; `session-byte-stream` owns xterm `onData` UTF-8 bytes and low-eight-bit `onBinary` bytes. The React adapter attaches no data listeners for the legacy owner; for the byte-stream owner it installs both raw listeners and transfers output `Uint8Array` chunks directly to xterm. The two owners must never be attached together. Session subscribers and state observers must be detached during disposal. Async startup and command completions must not update disposed sessions; startup errors transition to `failed`.

`LegacyTerminalSession` owns the existing `Shell` and `VirtualFileSystem`, keeping history and VFS behavior local. Its no-op `resize()` is intentional: `FitAddon` sizes the lightweight xterm and there is no remote process to signal.

`V86TerminalSession` is opt-in and creates a dedicated module Worker only after the visitor selects OS preview. The Worker validates the exact same-origin guest manifest, boots the pinned Alpine release in v86 with no network device, and transfers raw COM1 bytes to xterm without interpreting terminal output as readiness. UART1/COM2 uses the versioned `BOS1` frame format. The host decoder rejects malformed frames, unknown fields/operations, wrong sessions, invalid values, and non-contiguous sequence numbers; any such failure permanently removes COM2 action authority for that Worker while leaving an already-running guest's raw COM1 typing and Ctrl+C available. `guestBuildId` is the 64-character lowercase SHA-256 digest of the manifest's generated `alpine/9p/fs.json` asset, not the release path or version string.

`inputEpochAck` only acknowledges a COM1 input epoch; independent UARTs mean it cannot prove that bytes have traversed ttyS0 and the guest's tty/pty/ZLE queues are drained or that the current prompt is clean. It must never authorize a quick action. A separate guest-enforced fence must cover cumulative COM1 byte consumption, pending input queues, and current shell state before quick actions can be enabled. That fence and the complete COM2 contract remain unconfirmed with the Systems-owned guest, so the host currently rejects and disables all guest quick-action dispatch.

Resize and locale updates use bounded typed COM2 frames. Quick actions use a fixed action enum, never shell text. Guest portfolio requests accept only the canonical portfolio link IDs; `copyContact` is restricted to `quick-mail`. The host maps open requests through an own-key allowlist and shows at most one pending confirmation. Browser open/copy APIs execute only in a fresh direct host user gesture; confirmation is consumed before invoking them. Stop/reset detaches session listeners, waits for the Worker teardown acknowledgement, force-terminates after a two-second bound, and serializes replacement Workers so only one emulator owns resources at a time. Serial output is batched into a fixed 64 KiB buffer; overflow fails the session closed.

Development and production both register `/browser-os` before SPA fallback, return JSON 404s for missing assets, and revalidate generated guest assets because the writable filesystem and initrd may change while the release URL stays fixed. The manifest is fetched with no-cache; it cannot make mutable runtime files immutable.
